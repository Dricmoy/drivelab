# Build DriveLab and its driving replay workspace

This is a living execution plan. Keep Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective current. It follows the execution-plan skill.

## Purpose / Big Picture

DriveLab is a portfolio project for autonomous driving planning. A user selects a road scenario, runs a baseline or a trajectory planner, replays each decision, inspects chosen and rejected paths, and compares measured collisions, road departure, progress, and comfort. The road viewer is the primary product surface. Dataset scenarios come from local Waymo Open Motion TFRecords and run through Waymax; deterministic synthetic scenarios make the app usable before the user's download is available. Data provenance and simulation engine appear on every report.

## Surprises & Discoveries

Waymax uses JAX and requires Python 3.10 or later; the system Python is 3.9, but Homebrew Python 3.12 is installed. No dataset path has been supplied yet. The loader must make absence visible and use genuine decoded data when it is supplied.

The pinned Waymax StateDynamics environment has an upstream action_spec scalar-bound indexing bug. Directly constructing and validating actions works; reset, compiled stepping, overlap, and road-departure metrics pass without modifying the installed dependency. The independent verifier records the bug. Waymax also averages vehicle dimensions across future frames; the importer retains raw TFExample dimensions and uses current/past estimates instead.

Initial wide-map screenshots made the cars too small. A viewport that follows the ego, with an explicit full-scene reset, makes candidate paths readable on desktop and mobile. The inspector scrolls independently so long explanations do not create blank space below the replay.

The first eight demonstration actors were stationary or followed straight constant-speed motion, so either forecasting mode correctly produced identical candidate scores. Turning traffic adds observed yaw-rate changes and verifies the trained predictor materially changes scores once history exists. The first step still falls back to constant velocity. A learned predictor is not claimed to improve every scene.

The settings dialog initially changed live settings before Apply, and evaluation labels reflected new settings even when old results remained. Settings now use a draft, Escape discards it, and result labels are derived from persisted run settings. Small working copy was darkened after screenshot review to improve readability.

Repeated testing made Saved runs slow because the list returned complete trajectories for 50 entries. It now returns RunSummary objects without frames; evaluations also retain constituent run IDs and summaries instead of duplicating trajectories. Full replays remain accessible through GET /api/runs/{id}. New SQLite reports are losslessly compressed with a DLZ1 prefix; legacy text JSON is still decoded. No existing report is deleted or rewritten.

The official Waymax repository contains waymax/dataloader/testdata/tfrecord_with_routes, referenced by its own test utilities, but the package wheel omits that binary. The prior source checkout supplied it for an additional compatibility check. Its first record has a scenario ID, 30,000 map samples, 69 parsed lanes and five current actors; its origin is conservatively recorded as waymax-testdata rather than inferred to be a downloaded Waymo shard. Complete paired stepping passed. This provides broader geometry coverage without substituting it for the original real-download requirement.

The Rust scorer preserves the SAT projection tolerance, touching-edge overlap, unpadded clearance and 100-meter cap of NumPy. Local native tests proved identical decisions across full rollouts, while the independent 20-record fixture check proved matching final Waymax metrics. Kernel timing improvements are much larger than full-rollout improvements because road checks, candidate generation and report assembly remain Python work. Timing is an empirical local result, not a safety result or universal hardware claim.

Screenshot review after repeated imports exposed a layout regression: the taller library stretched the grid row, and main's vertical auto margins centered the replay beneath a large blank region. Main now stays top-aligned; on desktop the scenario list scrolls within a viewport-sized sidebar while Saved runs stays accessible. Mobile retains its horizontal library. Browser assertions check the replay heading remains near the top and history stays in the viewport as persisted scenes accumulate.

## Interfaces and Dependencies

GET /api/health reports backend, dataset, and Waymax availability. GET /api/scenarios lists scenario summaries. GET /api/scenarios/{id} returns geometry and initial scene. POST /api/runs accepts scenario_id, planner (baseline or lattice), and config containing target_speed, safety_margin, horizon, and prediction (constant_velocity or learned). GET /api/runs/{id} returns a full report, GET /api/runs lists saved RunSummary objects, omitting frames. POST /api/evaluations runs both planners on selected scenarios and returns paired RunSummary objects and aggregate metrics; each run ID retrieves its complete replay. POST /api/datasets/import accepts a local path and bounded limit. GET /api/model reports training/checkpoint status; POST /api/model/train accepts bounded integer seed and epochs. Simulation execution stays server-side. DRIVELAB_DB and DRIVELAB_FORECAST_PATH can override local database/checkpoint paths for isolated tests.

The UI receives Scenario with id, name, description, source, dt, duration, bounds, road_polygons, lanes, route, ego, actors, tags. RunReport contains id, scenario_id, planner, config, source, engine, scoring_backend, timing, metrics, frames, failures, and created_at. Config also contains scoring (auto, numpy or rust). Each frame contains time, ego, actors, actor_forecasts, candidates, selected_candidate, explanation, and metrics. Older reports may lack scoring_backend, timing, config.scoring and actor_forecasts; the UI preserves them without inventing missing data. Coordinates use meters; times use seconds. Every implementation change must preserve this contract or update both producers and consumers.
